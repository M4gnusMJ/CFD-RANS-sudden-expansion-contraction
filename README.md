# CFD Assignment 3 — Group 22

```
base_case/      OpenFOAM case (fields, system/, foam_functions)
case_design/    mesh generator + analytical baseline
postprocess/    GCI and plotting scripts
Allrun.sh       runs all three mesh levels
run_<level>/    generated by Allrun.sh, not in git
```

Everything is driven from the primary choices at the top of
`case_design/case_design.py` (nu, d1, d2, Re1, y+ target, wedge angle).
Change one there, re-run the script, and the meshes, the analytical curve,
the post-processing and the solver inlet BCs all follow. Do not hard-code
numbers anywhere else.

## 1. Generate the meshes

Plain Python, outside the container:

```bash
python3 case_design/case_design.py
```

Writes `blockMeshDict.coarse/.medium/.fine` (16k / 36k / 81k cells),
`design_summary.txt` with every parameter and where it comes from,
`analytical_pressure.csv/.png`, `case_params.json`, and
`base_case/0/include/initialConditions` (inlet U, k, epsilon, omega).

## 2. Run the simulations

`blockMesh` and `simpleFoam` only exist inside the OpenFOAM container, so
start it from the repo folder first:

```bash
cd /path/to/repo
~/OpenFOAM-work/openfoam-docker
```

Then, inside the container:

```bash
./Allrun.sh                  # coarse, medium and fine
./Allrun.sh medium fine      # only the levels you name
```

For each level `Allrun.sh`:

1. copies `base_case/` to `run_<level>/`, so the three results coexist —
   the GCI study needs all three at once,
2. drops `case_design/blockMeshDict.<level>` into `run_<level>/system/`,
3. runs `blockMesh`, `checkMesh` and `simpleFoam`, each logged to
   `run_<level>/log.<step>`,
4. prints the checkMesh summary (cell count, aspect ratio, non-orthogonality,
   skewness) and the solver's own y+ min/max/avg,
5. writes `postprocess/data/<level>_axis.csv` (x, p along the axis) and
   `<level>_yplus.csv` (x, y+ per wall face).

If a step fails it stops there and prints the last 25 lines of that log, so
the error is on screen; the full log stays in `run_<level>/`.

Rough wall-clock on a laptop: coarse ~10 min, medium ~40 min, fine ~1.5 h.

### Where the results end up

```
run_<level>/<iter>/            converged fields (U, p, k, epsilon, nut)
run_<level>/constant/polyMesh/ the mesh as run
run_<level>/system/            the setup as run
run_<level>/log.*              blockMesh / checkMesh / simpleFoam output
run_<level>/postProcessing/    raw function-object output
```

`run_*/` is gitignored — the two CSVs per level under `postprocess/data/` are
what gets committed. To look at a run in ParaView: `paraFoam -case run_medium`
inside the container, or `touch run_medium/run.foam` and open that file.

The function objects that produce the sampled data live in
`base_case/system/foam_functions`, pulled in by `controlDict`. Use only `//`
comments in that file — a `*/` inside a block comment (e.g. in a glob pattern)
ends the comment early and OpenFOAM chokes on the rest.

## 3. Post-process

Back outside the container:

```bash
python3 postprocess/plot_pressure.py
python3 postprocess/gci.py
```

`plot_pressure.py` reads `postprocess/data/<level>_axis.csv`, compares the
three levels against `analytical_pressure.csv` and extracts the pressure
drops. `gci.py` loads the three axis CSVs directly and uses the same pressure-slope
fit to calculate the inlet Darcy friction factor on each mesh. It reads median
y+ from the corresponding yplus CSVs and cell counts and geometry from
`case_design/case_params.json`. It reports the apparent order, Richardson
extrapolation, percentage errors and GCI for both grid pairs (Fs = 1.25).
It requires NumPy, pandas and SciPy. The default data path works from any working
directory; use `--data-dir /path/to/data` to select another set of CSVs.

## Notes

- Keep Nextcloud sync paused while working in this folder. It has silently
  reverted commits and left `controlDict-1`-style conflict copies behind.
- Wall `epsilon` is `fixedValue 1e-10`, not `epsilonWallFunction`:
  LaunderSharmaKE solves for epsilonTilda (zero at the wall), while the wall
  function imposes the log-layer value, which is meaningless at y+ = 1.
- Pressure uses PCG/DIC, not GAMG — GAMG agglomeration hits a floating-point
  exception on the high-aspect-ratio near-wall cells.
